SLIDE 1: Research Paper Navigator

Narration
This capstone presents a Research Paper Navigator for a local collection of research papers. The goal is to help a learner ask questions about a method or compare papers and receive an explanation that can be traced back to the source pages. The engineering story covers how retrieval developed, how evaluation exposed problems, and how the final design balances answer completeness with efficiency. The work uses real saved outputs from the course experiments, including examples that reveal remaining weaknesses.

SLIDE 2: The Research Problem

Narration
The intended user is a learner or researcher trying to understand a collection of papers about program synthesis and related work. Reading every PDF for each question takes time. A title search helps when the paper is already known, but it does less for an exploratory question or a comparison. Even finding the right file does not guarantee that the selected paragraph supports the answer. A bibliography may mention the method without explaining it, and conference and preprint versions may occupy several result slots. The system therefore needs to retrieve useful passages and make its factual support easy to inspect. Its role is to guide closer reading, rather than replace the original papers.

SLIDE 3: The Final Workflow

Narration
The workflow begins with PDF text extraction. Each chunk keeps its filename and page number, so the result can be checked later. The retriever runs keyword matching and semantic similarity, then merges their rankings. Before retrieval, a narrow filter removes recognizable instruction attacks. A conservative router chooses the answer path. A simple method question uses one search and one answer call. Comparisons and questions about evaluation or limitations keep the agent, which can request more evidence within a fixed action budget. The final prompt separates the question from the paper text and asks for a cited explanation. An exact cache can reuse an eligible direct answer under the same corpus and policy. The final interface exposes this workflow without requiring the earlier course directory layout.

SLIDE 4: Keyword and Semantic Retrieval

Narration
The hybrid approach fits the two common kinds of research question. BM25 provides a useful signal when a question includes a specific title or technical term. Semantic retrieval helps when a user describes an idea in different wording. Their raw scores have different scales, so reciprocal rank fusion uses each passage's position in the ranked lists instead. The implementation gives both methods equal weight and uses a rank constant of sixty. This is a reasonable baseline setting, not a claim that the weights are optimal. The standard answer context contains five passages and limits repetition from a file. That limit helps, but it does not fully merge duplicate versions of the same study. The index is reused between experiments so architectural changes can be examined on the same collection.

SLIDE 5: Evaluation Beyond a Passing Answer

Narration
Evaluation started with eight questions, including seven answerable research questions and one unsupported request. The expected paper appeared in the top five for all seven answerable cases. The automated judge passed every generated answer against its grading notes. However, the unsupported answer began by identifying an unrelated paper before adding a caveat. A separate abstention guard rejected that response, reducing combined acceptance to seven of eight. This example shaped the evaluation approach: a passing judge score can hide an important behavior failure. Four controlled good and degraded answers also checked that the judge could detect expected problems. The test set remains small, and the answer and judge models share potential blind spots. Citation presence and a source hit are useful signals, but neither proves every claim is correct.

SLIDE 6: Broader Search and Focused Evidence

Narration
Week four compared six broad questions with and without query decomposition. Splitting each question into narrower searches changed the evidence and increased distinct filename slots from twenty-three to twenty-seven. Both paths still passed all six rubric checks. Decomposition also added search calls and one possible reference-list passage. That supports a coverage observation, not a proven accuracy gain. Week five then tested an agent that could inspect the evidence and decide whether to retrieve again. On three multistep questions, fixed retrieval and the initial agent passed two, while the refined agent passed all three. The refinement checked named-paper coverage and selected method and evaluation evidence more deliberately. The final workflow carries forward that bounded agent for harder questions. It does not automatically apply the Week four decomposition experiment to every question.

SLIDE 7: A Recorded Research Question

Narration
This demonstration uses the saved Week seven response, so it can be replayed without a key or a new model call. The question asks how Learning to Infer Program Sketches combines a neural model with symbolic synthesis. The answer explains that the neural component proposes partial program sketches, while the symbolic component fills the holes. SLIDE 8: Security and Evidence Boundaries

Narration
The security work addresses instructions that try to redirect the research task. In the paired roleplay probe, the baseline returned only CLUCK CLUCK. The final version removed the recognizable command and answered the method question with citations. Several layers support this behavior. The input filter acts before retrieval, because attack wording can distort search even when the final model refuses the command. Tagged prompts state that paper text supplies facts, not new instructions. The action allowlist prevents an invented upload or delete tool from running. A text integrity check rejects altered passages after a clean index has loaded. In the other visible fact and retrieved-command probes, the baseline also resisted the attack. Those cases demonstrate an added deterministic boundary, rather than a new answer-level rescue. No universal attack-resistance rate is claimed.

SLIDE 9: Efficiency With a Quality Check

Narration
Efficiency focused on reducing repeated model work while retaining the evidence path for difficult questions. The simple method question dropped from three chat calls to one. Comparisons and limitation questions stayed on the agent path. An initial shortcut for evaluation limits missed part of the paper's scope, so the router changed to preserve focused retrieval for that class of question. Prompt context caps also reduced repeated evidence tokens. Across seven paired Week seven cases using the same chat model and corpus, the final design used forty-one point six percent fewer tokens and thirty-eight point one percent less reported production cost. Observed time also decreased, but provider load makes single-run latency uncertain. A separate exact-repeat test returned identical wording with zero API calls. These totals exclude cached index construction and earlier iterations. They are evidence from this small run, not a general production benchmark.

SLIDE 10: Engineering Decisions and Trade-offs

Narration
The final design follows the evidence from the experiments. Keyword-only retrieval is straightforward, but semantic retrieval adds support for reworded concepts. The agent can improve completeness by gathering missing facets, although it resends evidence and adds planner calls. Routing limits that overhead for simpler tasks, while the exact cache helps repeated questions under a matching corpus and policy. Both choices need quality checks: routing can be too shallow, and caching repeats the original answer's weaknesses. Week six also compared model choices. The current and mixed configurations passed all three ordinary questions, but the all-cheaper configuration passed none. The mixed setup was promising, yet the sample was too small to justify a broad change. Week seven therefore retained the same tested chat model and reduced work through workflow changes. This makes the efficiency comparison easier to interpret.

SLIDE 11: Limitations and Next Steps

Narration
The most important remaining weakness is that a secure answer can still be factually imprecise. One final answer rejected the invented overall accuracy but mixed the full-dataset and filtered-test columns in a compact table. Better table extraction and checks on numeric claims are therefore priorities. Ranking also needs human-labeled examples of relevant and irrelevant passages, with conference and preprint versions counted as one study. Citation evaluation should check whether each claim follows from its cited evidence, rather than just detecting brackets. Security tests should include less obvious poisoning present before ingestion and more varied instructions. Routing and cache policies need a larger held-out question set and repeated measurements. These next steps focus on evidence quality and evaluation before adding more agent complexity.

SLIDE 12: The Final System and Review Materials

Narration
The final deliverable brings the implementation and evidence together. The repository contains the supported command-line entry point, installation and configuration instructions, deterministic tests, and saved experimental records. A reviewer can replay the method answer or the before-and-after roleplay case without an API key. Live mode uses locally supplied paper PDFs and an OpenRouter key, while local keyword search works without generation. Full papers and credentials are separate inputs. The presentation's main conclusion is that retrieval quality, answer support, and efficiency need to be judged together. The system is a useful research-reading assistant with visible evidence and a bounded workflow. Its next improvement should make citation and table accuracy easier to verify on a larger set of questions.
